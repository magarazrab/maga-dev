# 🐛 Сцена 5 — Ошибка — это нормально

> Но если что-то не работает — это нормально.

# **Ошибка ≠ провал.**

# 🤖 Сцена 6 — Как правильно использовать ИИ для исправления

> Никогда не пишите ИИ просто:

```text
Не работает, исправь.
```

> Это слишком мало информации.

> Лучше объяснить проблему.

Промт:

```text
Я создаю приложение AI Study Assistant.

Использую:
- HTML
- CSS
- JavaScript
- Python Flask
- SQLite

Проблема:
[опиши проблему]

Ошибка:
[вставь ошибку]

Ожидаемое поведение:
[что должно происходить]

Текущее поведение:
[что происходит сейчас]

Проанализируй проблему.

Не переписывай весь проект.
Сначала объясни причину ошибки,
а затем предложи точное исправление.
```

> Вот это уже хороший запрос для AI-разработчика.

# 📦 Сцена 7 — Подготавливаем проект

> Теперь нам нужно подготовить проект для запуска на сервере.

Промт:

**анализ → исправление → проверка.**

# 🌐 Сцена 8 — Что такое сервер?

> Теперь поговорим о сервере.

> До этого приложение работало на нашем компьютере.

> Но если мы хотим, чтобы его могли открыть другие люди, оно должно работать на компьютере, который постоянно доступен через интернет.

> Такой компьютер обычно называют **сервером**.

Показываешь:

```text
Твой компьютер
      ↓
Разработка
      ↓
Сервер
      ↓
Интернет
      ↓
👤 Пользователь
```

---

# 🚀 Сцена 9 — Что такое деплой?

> Есть ещё одно слово, которое вы сегодня должны запомнить.

# **Deploy — публикация приложения.**

> Простыми словами:

> Мы берём приложение с нашего компьютера и запускаем его на сервере.

```text
💻 Локально
     ↓
📦 Проект
     ↓
☁️ Сервер
     ↓
🌍 Интернет
```

> После этого приложение может получить публичный адрес.

> Главное — не просто копировать команды.

> Понимайте, что каждая команда делает.

# 📋 Сцена 11 — requirements.txt

> В Python-проектах есть очень полезный файл:

```text
requirements.txt
```

> В нём указываются библиотеки, которые нужны проекту.

Например:

```text
Flask
```

> Если проект использует дополнительные библиотеки, они тоже могут быть указаны там.

> Когда проект запускается на новом сервере, сервер понимает:

> «Ага, мне нужно установить эти зависимости».

---

# 🔐 Сцена 12 — Безопасность

> Перед публикацией есть ещё одна очень важная вещь — безопасность.

> Никогда не храните секретные ключи прямо в коде.

Например:

```text
API_KEY = "секретный_ключ"
```

> Это плохая идея.

> Вместо этого используются **переменные окружения**.

> И ещё:

> Не публикуйте пароли.

> Не отправляйте секретные ключи в GitHub.

> Не храните важные секреты прямо в HTML или JavaScript.

> Это особенно важно, когда ваше приложение начинает использовать настоящих пользователей.
